# DR-0011: peers は行の topic で、gateway の時刻更新は行 1 つ

Status: Accepted (2026-09-11。統括判断。v0.8.0 / v0.8.1 で実装)
Date: 2026-09-11
Sponsor: 統括判断 (storm 事故の原因側への対処)
関連: 設計 §6.2 (差分の粒度)、§4.3 (導出)、§7.4 (event の relay)、[DR-0009](DR-0009-daemon-derives-session-state.md)、[DR-0010](DR-0010-one-topic-mechanism-one-egress-layer.md)、[DR-0012](DR-0012-gateway-cache-window.md)

## 1. 背景

`peers` は当初 instance ごとの全量置き換えだった。この形だと、1 つのセッションの 1 属性が動くたびに、その instance の**全行**が frame になる。gateway は推論を毎秒何度も観測するので、`gateway_active_at` が動くだけで一覧全体が述べ直され、mesh 経由で fan-out して webui が振動した。

同時に、接続を持つセッションと失われたセッションを別の一覧にする案があったが、これは「1 つのセッションが両方の一覧に居る / どちらにも居ない」瞬間を作る。

## 2. 決定

### 2.1 `peers` は element 粒度で、行が識別を保つ

**繋がっているセッションと失われたセッションは 1 種類の行として流れる。** セッションが登録されたり黙ったりすることは、一覧の間を entry が移動することではなく、**識別を保った行の `state` が更新される**ことである。失われた行だけが持つ欄 (`last_seen_at`、`stopped_at`、resume に要る `model` と `effort`) は、その同じ行の、もう持たない接続の欄の隣に載る。

接続を持たない行は、接続についての欄 (`connected_at` / `last_activity_at` / `client_version` / `protocol_version`) を**一切持たない** — 名乗った client が居ないので、世代は推測せず未記載にする。挨拶が述べたこと (`repo` / `ws` 等) は、`sessions/` がその sid を名指す限り残る。

**1 つのセッションが両方に居ることは無い。** `last_live` から entry を外すのは再び生きていることであって、挨拶ではない (セッションの resume は新しいプロセスと新しい state file を作るが、そのどれも挨拶ではない)。

### 2.2 行ごとに「新しいか」を問う

element 粒度なので frame 単位の抑止は効かない。代わりに **前回送った行と違う行だけ**が frame に入る。比べ方は同じ (最後に送った形との比較) で、単位を値から要素に変えただけなので、topic の仕組みの中に 1 実装として住む (M5)。違いが無ければ frame は出ない。

**居なくなった行は不在では言えない**ので、`{sid, instance, removed: true}` の要素として去る。

差分は **購読者に送ったもの**に対して取る。だから最初の `snapshot` frame (全行) もその基準を作る。そうしないと、snapshot でしか流れたことのない行の退去が、誰も送っていない行の退去になり、誰にも届かない。

### 2.3 gateway が時刻を動かしただけなら、動くのは行 1 つ

属性は分類ではないので (DR-0009 §2.2)、**gateway がセッションをもう一度見たら、その 1 行が `peers` に出るだけで、他の行は述べ直されない**。

セッション domain 全体を計算し直すのは **窓が開いた瞬間だけ** — 行が節を移りうる唯一の瞬間である。窓の内側で見直された時は、その sid の行だけを組み直して述べる。推論は毎秒何度も観測されるので、**1 つの属性が「どのセッションが在るか」の読み直しを要求してはならない**。

推論をそのまま見たい client には `llm.requests` があり、そちらは一覧ではなく gateway の眺めである。

### 2.4 `agents` も同じ形

`agents` は `polled_at` を述べる。確認 poll のたびに変わるが、行の差が空なら frame は 1 つも出ないので、heartbeat にはなりえない。

### 2.5 relay も要素単位

peer が述べ直しただけの行は、中継する instance の購読者に届かない (§6.1 の抑止を要素単位で適用)。peer の snapshot frame (その instance の全行) は 1 行ではなく一覧の述べ直しなので、peer がもう持っていない行は中継側が `removed` として渡す。

## 3. 不採用

| 案 | 理由 |
|---|---|
| `peers` を instance ごとの全量置き換えにする | 1 セッションの 1 属性が動くたびに全行が frame になる (本番の storm の原因) |
| 接続の有無で 2 つの一覧に分ける | 1 つのセッションがどちらにも居ない / 両方に居る瞬間ができる。行が識別を保てば `state` の更新で済む |
| 接続を持たない行にも接続の欄を推測で埋める | 名乗った client が居ないのに世代を名乗ることになる |
| gateway がセッションを見るたびにセッション domain 全体を再計算する | 推論は毎秒何度も観測される。1 属性が一覧全体の読み直しを要求する |
