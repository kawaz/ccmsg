# DR-0008: 配送は直接経路を優先し、inbox を永続化する

Status: Accepted (2026-09-08。統括裁定 DV-Q1〜DV-Q4)
Date: 2026-09-08
Sponsor: 統括裁定 (2026-09-08)
関連: 設計 §6.5〜§6.8 (配送)、§2.5 (永続化するもの)、§4.1 (ハーネス)、[DR-0002](DR-0002-contract-holds-the-vocabulary.md)

## 1. 背景

契約の `message.send` が約束するのは「宛先の sid に届ける」ことだけで、届かなければ理由を返す。daemon 側は「届ける手段」と「届かない理由の判定」の 2 つを持つ。

v1 の daemon は topic の購読経由でしか届けられず、「まだ購読していないセッションには届かない」穴を **3 分の巻き戻し窓**で塞いでいた。時間で塞ぐ穴は、時間を伸ばしても塞ぎきらない。

## 2. 決定

### 2.1 手段は 2 経路、(a) を優先して失敗したら (b)

| 経路 | 中身 |
|---|---|
| (a) harness 自身の入口へ直接 | Claude Code: `sessions/<pid>.json` の `messagingSocketPath` へ繋ぎ、config home の 0600 鍵で認証して user frame を書く。Codex: `codex queue --thread <sid>` にテキストを渡す |
| (b) `inbox` topic の差分として push | 受け手が購読を持っている場合 |

(a) を優先する理由は 2 つ。

- **受け手が ccmsg の常駐プロセスを持っていなくても届く。** 「まだ購読していないセッションに届かない」穴が、時間の窓ではなく**経路の性質として**消える。**入力が `sessions/` だけである**ことは同じ性質の裏側で、宛先の解決も書き込みも「挨拶を聞いたことがないセッション」に対して成り立つ — 再起動した instance にとっては全部がそれである
- (b) は ccmsg 自身のプロトコルなので、(a) が使えない相手 (世代不一致 / socket が無い / 鍵が読めない) でも働く

(a) は **条件が全部揃った時だけ**使う。1 つでも欠けたら、それ以上の判断なしに (b) へ落ちる。

### 2.2 (a) の受領確認は別の socket で、肯定応答は無い

受け手は受け取った message には何も返さず、**受け取らなかった時だけ** `refused` / `denied` / `dropped` / `expired` / `held` を上げる。だから期限内の沈黙が「届いた」であり、どれかが来たら drop である。返事は message を書いた接続ではなく、user frame の `from` が名指した別の socket (0600) に届く。その socket は state ディレクトリではなく **相手の socket の隣**に置く — 受け手は返信先を検査し、自分の socket 名前空間の外を捨てるため。

期限の値には一次資料が無い (**暫定**)。言えるのは、受け手が同じ門の判断から receipt を上げるので、同じホスト上の UDS 1 往復の距離にあるということだけ。

### 2.3 (a) が drop した message を配送済みにしない

drop は「今は受け取れない」であって、「届いた」でも「宛先が居ない」でもない。配送済みにすると本文が消え、`session_not_found` にすると宛先が居ないことになる。**inbox に残して再提示の機会を待ち**、送り手には `delivered: false, reason: "throttled"` を返す。

再提示のきっかけは inbox の dequeue 条件 (同じ sid への次の `message.send` が (a) で通った / `inbox` が購読された / セッションが再び live になった) であって、**時間の経過ではない**。周期的な再送タイマーは持たない (M3 — 相手のトークンバケツの回復速度を述べた一次資料が無く、間隔は当て推量にしかならない)。送るのは 1 通ずつ古い順で、通らなかった最初の 1 通で止める。

### 2.4 inbox は永続化する

未配送の本文は **どこからも再構成できない**。送り手の `message.send` は既に応答を返して終わっており、「まだ届いていない」本文は transcript にも上流にも無い。daemon が失えば本文ごと消える。だから M4 の対象外であって、M4 の例外ではない (M4 が禁じるのは**派生値**の永続化)。

形式は append-only の jsonl で、配送できた時点で消し込む。append-only なので書き込みは 1 種類 (末尾への追記) に閉じ、書き込み途中の crash は末尾の行だけを壊す。

### 2.5 (b) の配送は at-most-once

frame を接続に書いた時点で配送済み。購読の snapshot は「その sid にまだ届いていない全部」で、**購読することが受け取ることなので**、snapshot を返すのと同時に inbox から消える。受け手が接続ごと frame を失ったら本文はどこにも無い。

渡したものを ack まで保持すると、inbox が「届いたかもしれないもの」を持つことになり、次の購読か次の (a) 提示が同じ本文を 2 度届ける。**1 通は 1 経路で出る** — (a) の提示中の message を snapshot から外すのも同じ規則で、提示の最中に来た購読が 1 通を 2 通にしない。

sid を持たない接続 (人が見ている) には空の snapshot を返す。topic が運ぶのはセッションに言われたことで、人はセッションではない。

### 2.6 保持期限と件数上限の値は契約が持つ

daemon は契約の値を参照するだけで、自分では決めない。理由も契約側に書く (7 日は `last_live` の保持窓に揃え、256 件は Claude Code 自身の受信キュー上限と対称)。

## 3. 不採用

| 案 | 理由 | 見直す条件 |
|---|---|---|
| 時間窓の巻き戻しで不達を救う | 配送保証の穴を時間で塞ぐことになる。inbox が「届いたか」を状態として持つので窓は要らない | inbox を持てない配送面 (受け手が自分の状態を持たない) が現れたとき |
| (b) だけで配送する | 受け手が購読するまでの穴が残り、時間窓が戻ってくる | (a) が harness 側から消え、最初の経路になるものが無くなったとき |
| (a) だけで配送する | 非公式プロトコルの世代が変わると配送が丸ごと消える | 非公式プロトコルが公式になり、世代変更が予告なく起きるものでなくなったとき |
| (a) で drop されたものを配送済みにする | 本文が失われる | drop が本文ごと返り、落ちたものを後から再構成できるようになったとき |
| inbox を揮発にする | 未配送の本文はどこからも再構成できず、再起動で消える | 未配送の本文が daemon の外にも持たれ、再起動が失わなくなったとき |
| 渡した message を ack まで inbox に残す | 「届いたかもしれないもの」を持つことになり、同じ本文が 2 度届く | — |
