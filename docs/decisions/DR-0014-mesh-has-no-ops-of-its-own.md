# DR-0014: mesh は専用 op を持たず、到達不能を通常状態として扱う

Status: Accepted (2026-09-08 に DV-Q11 / DV-Q12 を裁定。`mesh.*` を作らないのは 2026-09-11 の統括裁定 I1)
Date: 2026-09-11
Sponsor: 統括裁定 (2026-09-08 / 2026-09-11)
関連: 設計 §7 (mesh)、§9.5 (mesh のテスト)、[DR-0003](DR-0003-naming-rules.md)、[DR-0001](DR-0001-passkey-auth-for-people.md) (instance id と endpoint)、[DR-0004](DR-0004-config-edited-and-applied.md) (endpoints はデータ)

## 1. 背景

instance 同士のやり取りをどう表すかに 2 案あった。mesh 専用の op 族 (`mesh.*`) を足す案と、既にある挨拶と封筒で表す案である。

もう 1 つ、この mesh は **1 台が電源オフやスリープであることが通常状態**という性質を持つ (家の中の複数マシン)。到達しない peer を異常として扱うと、通常状態で起動できなくなる。

## 2. 決定

### 2.1 mesh は専用の op を持たない

instance 同士のやり取りは **`hello.instance` と、転送の封筒 (`RequestEnvelope`) の 3 欄**で表される。surface ごとに op を複製すると二重定義になる。

封筒が運ぶのは契約の 3 欄だけ (`to_instance` / `from_instance` / `hops`)。`hops` に既に自分が入っている request は捨てる (周回しない)。

### 2.2 転送先でも認可をやり直す

`locality: instance-local` の op は、対象を持つ instance が自分でなければ転送される。**転送先で §2.2 の 1〜6 段をもう一度通す。** 「A が既に認可したから B は信じる」は採らない — A が侵害されていたら B の認可が消えることになる。

判定の相手は封筒の `caller` (認証済み link が名乗った identity) であって、転送した instance の判定結果ではない。

### 2.3 到達しない peer は起動を止めない

答えなかった peer は記録され、dial の対象として残る。起動が失敗するのは **mesh が自分を名指していない (一致 0)** か、**1 つの住所に 2 行ある (一致 2 以上)** 場合だけ — 前者は誰も dial できない instance、後者はどちらを正式な名前とも決められない。

### 2.4 断絶した instance の全量は捨てない

捨てると、再接続で全量が戻るまで空になる。「到達不能」の印を付けて保持し、**再接続で置き換え、7 日で破棄する**。7 日は inbox / `last_live` の保持窓と揃えてある — 「その instance が 7 日戻らなければ、未配送の message も、以前走っていたセッションの記録もどちらも既に消えている」ため。片方だけ残しても参照先が無い。

断絶中の `instance-local` op は `instance_unreachable`。断絶は `hello` の応答と `instances` topic の `reachable` 欄に出る。`instances` が `peers` の行と別なのは、**mesh の眺めは 1 つの instance が自分の全リンクをまとめて読んだもの**であって、行の集合ではないからである。

### 2.5 1 つの id は 1 本の endpoint にしか束縛されない

名前を保証するのは運用者が配ったリストだけなので、そのリストが既に保証した束縛を保つ。別の endpoint に束縛済みの id を名乗る挨拶は、新しく来た側を close する。引っ越した instance が旧 URL でまだ生きている時がこれに当たり、直し方は **全 peer の `endpoints.json` から旧 endpoint を外すこと**であって、新しいリンクを勝たせることではない。

### 2.6 relay は中身を作り直さない

購読者が cluster 全体を見るために、instance A は各 peer の同じ topic を購読し、受けた frame を `instance` 欄を保ったまま自分の購読者へ流す。**A は中身を計算し直さない** — やり直すと同じ判断が発生元と A の 2 箇所に生まれる。

### 2.7 glare の解き方は「両端が同じ 2 つの文字列を比べる」こと

両側が dial した時は、両方を検証した後、`iss` (= endpoint URL) の辞書順が小さい側が自分の dial した接続を残す。規則の全体は **両端が同じ 2 つの文字列を比べて同じ結論に達すること**であって、どちらの接続が優れているかではない。

## 3. 不採用

| 案 | 理由 | 見直す条件 |
|---|---|---|
| mesh 転送のための新しい op を足す | 3 欄の封筒で足りる。surface ごとの op の複製は二重定義 | 3 欄の封筒では運べない転送 — 経路を述べる必要がある 2 hop 以上の中継 |
| 転送元の認可を信じて転送先では省く | 侵害された instance 1 つが cluster 全体の認可を無効にする | instance 間の信頼が cluster 全体で確立されるようになったとき (相互 attestation) |
| 到達しない peer で起動を止める | 1 台が電源オフやスリープなのがこの mesh の通常状態 | — |
| 断絶した instance の全量を捨てる | 再接続で全量が戻るまで空になる | — |
| relay 側で中身を計算し直す | 同じ判断が 2 箇所に生まれる | — |
| glare で新しいリンクを勝たせる | 名前を保証するのは運用者が配ったリストだけ | — |
